# SEO Handoff — wallBoard

این سند برای تحویل به متخصص SEO و برنامه‌نویس Django است. فایل‌های HTML فعلی، عنوان و توضیح اختصاصی هر صفحه، RTL فارسی، Open Graph پایه و `robots.txt` قابل خزش دارند؛ اما SEO عملیاتی نهایی بعد از تعیین دامنه و پیاده‌سازی رندر سمت سرور تکمیل می‌شود.

## کارهای آماده در فرانت‌اند

- زبان و جهت سند: `lang="fa"` و `dir="rtl"`.
- عنوان و meta description مجزا برای صفحات اصلی.
- Open Graph با `og:locale=fa_IR` و تصویر لوگوی برند.
- `robots.txt` با اجازه خزش عمومی؛ صفحات تراکنشی حساب، سبد، تسویه و علاقه‌مندی‌ها `noindex,follow` هستند.
- مسیر slug برای محصولات در داده‌ها آماده است؛ لینک پیش‌نمایش از `product.html?slug=...` استفاده می‌کند.
- تصاویر محصول از داده مرکزی خوانده می‌شوند و alt قابل تعریف دارند.

## مواردی که باید پس از تعیین دامنه انجام شوند

1. جایگزین‌کردن URLهای پیش‌نمایش با دامنه قطعی HTTPS.
2. افزودن canonical یکتا به هر صفحه؛ برای محصولات باید مسیر خوانا مانند `/products/pegboard-panel-30x30/` باشد.
3. ساخت sitemap.xml واقعی شامل صفحات indexable، محصولات فعال و دسته‌بندی‌های فعال؛ صفحات account/cart/checkout/favorites و صفحات داخلی مدیریت در sitemap نباشند.
4. افزودن `Sitemap: https://DOMAIN/sitemap.xml` به robots.txt.
5. تنظیم redirectهای 301 برای تغییر slug و آدرس‌های قدیمی.
6. رندر سمت سرور title، description، canonical، Open Graph و JSON-LD در صفحات محصول و دسته‌بندی؛ تغییر document.title با JavaScript به‌تنهایی برای SEO کافی نیست.
7. افزودن Product JSON-LD فقط با قیمت، ارز، موجودی، SKU، تصاویر و برند تأییدشده؛ هرگز قیمت/موجودی فرضی منتشر نشود.
8. افزودن BreadcrumbList و Organization/WebSite schema پس از تعیین دامنه و اطلاعات کسب‌وکار.
9. ثبت دامنه در Google Search Console و ابزارهای وبمستر مرتبط و ارسال sitemap.
10. بررسی index coverage، صفحات تکراری، پارامترهای فیلتر و pagination.

## پیشنهاد ساختار URL

- `/`
- `/shop/`
- `/categories/`
- `/categories/{category-slug}/`
- `/products/{product-slug}/`
- `/about/`
- `/gallery/`
- `/faq/`
- `/contact/`
- `/shipping/` و `/returns/`

صفحات تراکنشی مانند `/cart/` و `/checkout/` بهتر است noindex باشند.

## راهنمای محتوا

- برای هر محصول یک عنوان و توضیح یکتا بنویسید؛ از تکرار توضیح عمومی فروشگاه خودداری شود.
- ابعاد، جنس، ضخامت، روش ساخت، محتویات بسته و سازگاری فقط با داده تأییدشده درج شود.
- برای تصاویر واقعی، نام فایل توصیفی، alt دقیق، ابعاد صریح و WebP/AVIF تولید شود.
- صفحات دسته‌بندی باید توضیح مفید و منحصربه‌فرد داشته باشند، نه فقط فهرست کارت‌ها.
- نام برند `wallBoard` حفظ شود؛ نام‌های آزمایشی قبلی استفاده نشوند.

## Performance / Core Web Vitals

- تصویر Hero اصلی را preload کنید؛ سایر تصاویر lazy-load باشند.
- برای همه تصاویر width/height یا aspect-ratio تعیین کنید.
- فونت Vazirmatn را در صورت فراهم بودن فایل مجاز، self-host و subset کنید؛ در غیر این صورت بارگذاری Google Fonts را با `display=swap` نگه دارید.
- CSS/JS تولیدی را minify و با Brotli/Gzip سرو کنید.
- فایل‌های hashدار را با `Cache-Control: public, max-age=31536000, immutable` و HTML را با `no-cache` سرو کنید.
- Lighthouse موبایل و دسکتاپ را روی دامنه نهایی اجرا کنید؛ اعداد قبل از deploy واقعی قابل ادعا نیستند.

## مواردی که فعلاً نباید منتشر شوند

- قیمت و موجودی محصولات که هنوز تأیید نشده‌اند.
- امتیاز و نظر مشتری ساختگی.
- ظرفیت تحمل وزن یا سازگاری تأییدنشده قطعات.
- تصاویر مفهومی CSS به‌عنوان عکس واقعی محصول.
